1 · How it works

1. Architecture and stack

Every module is its own n8n workflow with its own form, so each can be demoed alone. A control hub (served by n8n) shows the results of all four, live from HubSpot and Google Drive, and a master workflow can run M1, M3 and M2 in order from one form. The only human step is the trigger (upload a list or a recording link), which stands in for the webinar platform's webhook. Every decision after that is made by AI and checked by code.

  1. Inputs: registrant export (Zoom format), recording or transcript, watch and CTA links.
  2. M1 Enrich: clean, dedupe against HubSpot, Clay, DeepSeek, ICP score, route.
  3. M2 Email: Deepgram transcript, takeaways, fact guard, three segment emails through HubSpot.
  4. M3 Content: blog, YouTube pack, infographic, social posts, Gemini visuals, Google Drive.
  5. M4 Intelligence: live dashboard with anomalies, interest scores and an AI narrative.

3 · Module 1

3. Module 1: Lead list enrichment

Upload the registrant export to the M1 form. Three n8n lanes do the rest: intake (clean, dedupe, save to HubSpot, send to Clay), enrichment (Clay calls back per row, DeepSeek classifies, code scores and routes) and a live report.

Brief asks forWhat the build does
Fuzzy match and dedupe against HubSpotIn-file dedupe (same email, or same person at the same company via Jaro-Winkler + company token match, incl. swapped name order), then HubSpot matching: exact email (1.0), same name + company (0.95, merge), similar name + company (0.8, flagged for review). Every decision is logged with its reason. Result: 68 → 64 people, 13 merged, 1 "Priya vs Priyanka Das" flagged, two different "Rahul Sharma"s kept apart.
Infer missing title, function, seniority, size, industryClay first (company size, industry, HQ, LinkedIn); DeepSeek fills what is missing and records each inferred value with a confidence and basis (139 inferred values across the list). Country is inferred from the phone code or company HQ.
Enrich company data, score ICP fitEditable rubric (size, region, HR-buyer persona, seniority, attendance and engagement) plus a one-line AI reason. Tier A needs an HR-buyer persona; students, consultants and vendors are capped.
HubSpot-ready output, completeness above 90%Completeness 42% → 99% across 14 SDR fields. Region assigned, owner routed (Tier A to senior SDR, others by region), lifecycle set forward-only (attended + Tier A/B + known role = MQL). CSV download in the hub.
4 · Module 2

4. Module 2: Post-event communications

The "Event closed" form takes the recording link (or a transcript as a fallback). Deepgram transcribes it with speaker labels, DeepSeek extracts takeaways with verbatim quotes, code fact-checks them, DeepSeek writes the copy, and HubSpot sends and tracks three segment emails.

Brief asks forWhat the build does
Segment-specific copy and subject variantsAttendee thank-you (recording + 3 takeaways), no-show catch-up (recording first + takeaways), speaker thank-you (performance snapshot). Three subject lines per segment, assigned A/B/C per contact.
Short key-takeaway snippetsThree "so what for an HR leader" snippets, each paired with a verbatim, timestamped quote that passed the fact guard.
Personalise by role or industryA persona opener (HR leader, HR practitioner, HR tech, talent, finance/ops) and an industry line, written into each contact's HubSpot record and merged into the email with personalisation tokens.
Speaker performance snapshotComputed by code, never generated: registrants, attendance rate, average minutes, % staying 30+ min, questions, % Director+, top industries, plus the speaker's best verified quote.
Dispatched within 24 hours, logged with UTMsSent through HubSpot marketing email within about a minute of the form. Segment lists and emails are created per run; every link carries utm_source, utm_medium, utm_campaign and utm_content = segment + variant. Sends, opens and clicks are tracked by HubSpot.
5 · Module 3

5. Module 3: Content repurposing

From the recording, M3 extracts key moments, insights, verbatim quotes and data points, fact-checks them, then generates each asset, validates it against hard rules in code, creates the visuals, and saves everything to a per-event Google Drive folder as formatted Google Docs, tagged by event, with a README index and QA report.

Brief asks forWhat the build does
Blog draft, 800-1200 wordsGenerated as structured parts and assembled by code; quotes are inserted from the verified list (guaranteed word-for-word); length enforced by code (expand pass if short, trim whole secondary paragraphs if long).
YouTube chapters, description, thumbnail briefChapters validated against YouTube's rules (start 00:00, 3+, 10s apart). Compared with the creator's official chapters: 6 of 7 within 90 seconds. Description + tags + thumbnail brief, and a finished thumbnail image.
Infographic outline with data points5-7 sections built only from fact-checked data points and quotes, plus a data-accurate HTML version and a rendered poster.
5-10 social posts with distinct hooks5 LinkedIn + 5 X posts; one idea per post; hook types distinct per platform; X length checked.
Image generation, saved to a shared drive, taggedGemini 3 Pro Image in two house styles chosen from a style test; images throttled to respect quota with automatic retries; a note is saved instead if an image fails, so the run still completes.
6 · Module 4

6. Module 4: Lead intelligence dashboard

A live page that reads HubSpot on every load. Code computes the metrics and statistical anomaly candidates; DeepSeek judges which anomalies matter, adjusts interest scores with a reason, and writes the narrative. A number guard checks that every number in the narrative exists in the data.

Brief asks forWhat the build does
Attendee-to-MQL conversionKPI cards and a Registered → Attended → MQL → SQL funnel (88% of attendees became MQLs; 3 SQLs from demo requests).
Top engaged accounts and buying committeesAccounts ranked by combined interest; a buying committee is 2+ people across 2+ functions, with each member's role and score.
Score lead interestFormula base (attendance, minutes, questions, opens, clicks, page views, form fills, pricing views, recency decay) plus an AI adjustment of up to ±15 with a one-line reason.
Detect anomaliesCode flags candidates (per-account z-score spikes, silent Tier-A MQLs, no-shows with high intent); AI keeps what matters, removes duplicates and gives each one an SDR action. It found all three planted patterns.
Stage movement over 7, 14, 30 days; AI narrative refreshed on loadLifecycle stage entries per window from HubSpot stage history; the narrative is regenerated on every page load.
7 · Control hub and "Run everything"

7. Control hub and "Run everything"

The hub is a single page served by n8n. It has a page per module, read live from HubSpot and Drive, and a "Run workflows" page linking every form. API tokens stay inside n8n.

The master workflow takes everything in one form (registrant CSV, recording link or transcript, links, mode) and calls the modules in order: M1, then a wait while Clay and DeepSeek enrich every contact, then M3, then M2. Each module also has a "When called by MASTER" trigger next to its form, so the modules stay independent. The modules are individually tested end to end; the master is built and wired, and was not re-run for the submission to avoid duplicate sends.

8 · Reliability

8. AI guardrails and failure handling

GuardrailWhereWhat it prevents
Fact guardM2, M3Every quote, evidence line and data point must appear word-for-word in the transcript; anything else is dropped and listed in the QA report. Emails are refused if fewer than 3 takeaways pass.
Number guardsM2, M3, M4Numbers in emails, blog, infographic and narrative must exist in the transcript or the data.
Rules enforced in codeM3Blog word range, meta length, YouTube chapter rules, X 280 characters, distinct hooks, 5-7 infographic sections.
Computed, not generatedM1, M2, M4ICP points, completeness, speaker snapshot, funnel, stage movement and anomaly statistics are code; AI adds judgement and language.
Transparent inferenceM1Every AI-inferred value is stored with a confidence and basis; the AI is told not to invent people or facts.
Tolerant JSON handlingAllRepairs common LLM JSON slips (fences, line breaks, stray quotes, bare hashtags, trailing commas); one failed asset degrades gracefully instead of stopping a run.
Retries and throttlingAllHTTP and Drive retries; Clay callbacks rate-limited for HubSpot; image calls spaced for quota.
Safe sendingM2Drafts-only mode; demo contacts on reserved domains; forward-only lifecycle changes in M1.
SecretsAllTokens live in n8n credentials only; the browser never sees them; the Clay callback uses a secret path; the image proxy serves only content-package images.

9. Testing, costs and next steps

How to see it live

  • I can run the whole build live over a call: the hub, each module form, and the results in HubSpot, Clay and Google Drive.
  • Every module runs from its own form or from the master form; M2 and the master have a Create drafts only mode so a demo sends no email.
  • Sample inputs are in the repository (data/registrants_zoom_export.csv; transcript via the recording link).

Run cost

A full run costs a few rupees of LLM usage (DeepSeek) plus about three image generations; Clay, Deepgram, HubSpot, n8n and Drive run on free tiers or trial credit at this volume.

Next steps for production

  • Trigger from the webinar platform (Zoom "recording completed" and registrant APIs) instead of forms.
  • Paid Marketing Hub so every segment email is delivered; HubSpot workflows for follow-up sequences on the MQLs.
  • Replace seeded engagement with HubSpot email events and page analytics; schedule the dashboard sync.
  • A human approval step before sending (n8n "send and wait"), and per-brand style settings for images.
